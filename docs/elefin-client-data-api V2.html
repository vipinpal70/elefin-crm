Quick start

From zero to your first response in three steps.

  1. Get your credential

    Elefin issues it from the CRM. You receive it once, on screen, at the moment the key is created. It is hashed on save and cannot be recovered. Store it the way you store a database password.

  2. Call /me

    It needs no permission and confirms the credential works, which key type you hold, and which abilities are on it.

    curl https://el.theloginarea.com/api/v1/me \
  -H "Authorization: Bearer {key}.{secret}"
  3. List your clients

    Page through with page and per_page. Nothing you pass widens what you can see.

    curl "https://el.theloginarea.com/api/v1/clients?per_page=50&page=1" \
  -H "Authorization: Bearer {key}.{secret}"

Authentication

Every request carries the credential. There is no login step, no token exchange and no refresh.

Your credential has two halves joined by a dot: a public key and a secret. Send them together:

Authorization: Bearer fxcrm_pk_XXXXXXXX.fxcrm_sk_XXXXXXXX

A header pair is also accepted, for clients that cannot set an Authorization header:

X-API-Key:    fxcrm_pk_XXXXXXXX
X-API-Secret: fxcrm_sk_XXXXXXXX
Neither half works alone

The public key is an identifier, not a credential. Sending either half by itself returns 401. Send the whole dotted string, with no braces or whitespace around it. The {key}.{secret} in the examples is a placeholder, not literal syntax.

Handling the credential

  • Keep it server-side. It carries no per-user scoping, so anything holding it can read your whole book.
  • Never ship it in a mobile app, browser bundle or public repository.
  • Lost it? It cannot be recovered. Ask Elefin to regenerate the secret, which invalidates the old one immediately.
  • Keys can carry an expiry date and can be deactivated at any time. Both surface as 401, so treat a sudden 401 on a previously working integration as a key lifecycle event, not a bug in your code.

What your key sees

A Partner key is bound to one partner: you. That binding is applied on the server, on every endpoint, and cannot be changed after the key is issued.

  • You do not pass a partner id. There is no parameter for it. Scoping is implicit in the credential.
  • Every list is already filtered to the clients you referred. meta.total is your count, not the broker's.
  • Records outside your book return 404, identical to records that do not exist. This is deliberate. You cannot use the API to discover whether a client id or MT5 login exists elsewhere in the CRM.
  • Only real trading accounts are reported. Demo accounts never appear.

Abilities

Your key carries a list of abilities. They decide which endpoints answer you and, in one case, which fields come back. Call /me to see what yours holds.

AbilityUnlocks
clients.readClient list. The six client and account endpoints: /clients, /clients/lookup, /clients/{id}, /accounts/{login}, /accounts/{login}/trades, /accounts/{login}/positions
clients.piiContact details. Unmasks email and phone on client responses. Grants no endpoint of its own.
clients.pii is a modifier, not a grant

It changes what a response contains; it never opens a route. A key holding clients.pii and nothing else receives 403 everywhere except /me.

It is also granted only on purpose. Where a key created with nothing selected receives every other ability, this one is withheld unless someone ticked it by name.

Without clients.pii, email and phone are returned masked rather than removed. The keys are always present. Do not parse the masked form or use it as an identifier; treat it as display text only. Every other field, including name and country, is returned regardless.

Conventions

True of every endpoint. Build these into your client once and stop thinking about them.

Response envelope

Every response, success or failure, is wrapped the same way.

{ "success": true, "message": "Success", "data": { … } }

List endpoints nest a paginator inside data. Note the double nesting: data.data holds the rows.

{
  "success": true,
  "message": "Success",
  "data": {
    "data": [ … ],
    "meta": { "current_page": 1, "per_page": 50, "last_page": 7936, "total": 39679 }
  }
}

Pagination

ParamNotes
per_page1–200. Default 50. limit is accepted as an alias on some endpoints.
pageFrom 1. Past last_page you get an empty data array, not an error.

Units and formats

  • Money is USD. Where a payment was taken in another currency, the row also carries paid_amount, paid_currency and exchange_rate.
  • Timestamps are UTC, ISO-8601, with a trailing Z, for example 2026-01-15T09:00:00Z. Date-only filters take YYYY-MM-DD.
  • Volume is in lots.
  • MT5 logins are strings, not integers. They exceed 32-bit range and have leading-digit significance, so do not cast them.
  • Money fields arrive as JSON numbers. Use a decimal type on your side; do not accumulate in binary floats.

Rate limiting

60 requests per minute per key. Every response carries X-RateLimit-Limit and X-RateLimit-Remaining. Exceed it and you get 429 with a Retry-After header in seconds. Wait that long rather than retrying immediately. For bulk syncs, one request every 1.1 seconds keeps you comfortably inside the limit.

Endpoints

All seven are GET. The API is read-only. There is nothing you can create, change or delete through it.

Your key decides which fields come back

Field access is set per key when it is issued, so two keys can call the same endpoint and receive different shapes. Withheld fields are absent from the response entirely rather than returned empty, so read a missing key as withheld, not as null. Call an endpoint once to see exactly what yours returns, and ask your Elefin contact if something you need is not there.

GET/meno ability

Who you are, what your key can do, and how far back the data goes. Call this first, and on startup. It is the cheapest way to confirm a credential still works.

Example response 
{
  "success": true,
  "message": "Success",
  "data": {
    "key": {
      "name": "Test integration",
      "abilities": ["clients.read", "clients.pii"],
      "rate_limit_per_minute": 60,
      "expires_at": null
    },
    "scope": { "type": "partner", "partner": { "id": 1, "name": "Test Partner" } },
    "totals": { "clients": 100 },
    "data_availability": {
      "transactions_from": "2026-01-01T00:00:00Z",
      "trades_from": "2026-01-01T00:00:00Z"
    },
    "conventions": { "currency": "USD", "timezone": "UTC", "volume_unit": "lots" }
  }
}
GET/clientsclients.read

Your referred clients, each with funding, account and trading totals already aggregated. This is the endpoint most integrations are built on.

ParamNotes

pageFrom 1.
emailRestrict to one client by registered email address.
sortregistered_at (default), client_id, name.

registered_fromOn or after this date, YYYY-MM-DD.

GET/clients/lookupclients.read

Answer one question, “is this email address one of my clients?”, without paging the roster. Built for signup checks and support tools.

ParamNotes
emailThe client's registered email address. Required.

If the address is not one of yours, you get affiliated: false and nothing else. You get that same answer whether or not that person exists in the CRM at all. You cannot use this to test whether an address is registered with Elefin.

The response echoes the address you submitted even without clients.pii, since it discloses nothing you did not already have.

GET/clients/{id}clients.read

One client, plus a per-account breakdown under accounts.items. Use this for a detail view; use /clients for lists.

Everything in a /clients row, and additionally:

FieldNotes
accounts.logins[]Every MT5 login on the client. Same values as accounts.items[].login.
accounts.items[]One object per account: login, affiliated, account_type, platform_group, currency, opened_at, balance, equity, credit, margin, free_margin, leverage, trading_enabled, total_deposit, total_withdrawal, net_deposit, lots, trades, net_profit, last_trade_at, commission, updated_at
commission_earnedCommission attributable to this client.

A client id outside your book returns 404, indistinguishable from one that does not exist.

GET/accounts/{login}clients.read

Confirm an MT5 login belongs to you, and read its balance, lifetime deposits, traded lots, last trade and commission. It carries client_id, so an account can always be traced back to the client who owns it.

A login that is not yours, or does not exist, returns affiliated: false. Same answer for both, by design.

GET/accounts/{login}/tradesclients.read

Closed positions on one account, newest first, already aggregated from raw MT5 deals into one row per position with a stable trade_ticket_id.

ParamNotes
limit1–200, default 50. per_page accepted as an alias.
pageFrom 1.
fromClosed on or after this timestamp.
toClosed on or before this timestamp.
symbolOne instrument, e.g. XAUUSD.

A login outside your scope returns 403 with unaffiliated, rather than the 404 used elsewhere. Handle both.

GET/accounts/{login}/positionsclients.read

One row per position currently open, marked to the latest sync. A trade only reaches /trades once the position is fully out, so this is the endpoint that makes a mid-trade or partially-closed account visible.

trade_ticket_id matches the closed-trade row the position will become, so you can follow one position from open to close across both endpoints.

Read as_of before trusting an empty list

Positions are served from a snapshot the platform sync refreshes each minute, not from MT5 inside your request. An account with nothing open and a sync that has stopped both return an empty list. A stale or null as_of means unknown, not flat.

A login outside your scope returns 403 with unaffiliated.

Errors

Failures use the same envelope, with success: false and a human-readable message.

{ "success": false, "message": "This API key does not have the 'clients.read' permission." }
CodeMeaningWhat to do
401Missing, malformed, inactive or expired credential.Check the dotted format first. If it was working yesterday, the key was deactivated or its secret regenerated. Ask Elefin.
403Your key lacks the ability for this endpoint, or its partner no longer exists.Not retryable. The message names the missing ability. Compare against /me.
404The record does not exist, or is outside your scope. The two are deliberately indistinguishable.Do not interpret as "deleted". Treat as "not mine".
429Rate limit exceeded.Sleep for Retry-After seconds, then retry. Do not retry immediately.
Retry only 429 and 5xx

401, 403 and 404 are terminal. Retrying produces the same answer and burns your rate limit. Back off exponentially on 5xx.
